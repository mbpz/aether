# EP-01 安全沙箱执行层

> **Epic 目标**：用 WASM + eBPF 替代 Docker 容器，从物理层面杜绝 Prompt Injection 和隐私数据外流。

- **优先级**：P0（阻塞性）
- **阶段**：阶段一（第 1-2 周）
- **状态**：📋 待开始

## 背景 & 问题

Manus 使用 Docker 容器作为沙箱，存在容器逃逸、网络外泄等风险。本 Epic 通过以下方式超越：
- **WebAssembly（WASM）**：在用户态执行代码，天然隔离，无法直接访问宿主机系统调用
- **eBPF**：在内核层监控所有系统调用和网络请求，违规行为直接在内核层丢弃

## 技术要点

```
执行层架构：
  用户请求 → WASM Runtime（代码执行）
                ↓
  eBPF Hook（内核层监控）→ 违规? → 丢弃 + 写审计日志
                ↓ 合规
  返回执行结果
```

### 核心组件
- `wasm-runtime`：基于 Wasmtime 或 Wasmer 的代码执行引擎
- `ebpf-firewall`：内核级网络防火墙，基于 libbpf
- `audit-logger`：审计日志收集器，支持 SOC2 格式输出
- `codeact-engine`：支持 Agent 自调试的动态脚本执行器

## 验收标准

- [ ] Agent 生成的代码在 WASM 沙箱中执行，无法读取宿主机文件系统
- [ ] 尝试连接非授权服务器的请求被 eBPF 在内核层拦截，响应时间 < 1ms
- [ ] 审计日志实时记录所有系统调用，格式兼容 SOC2
- [ ] CodeAct 自调试闭环：Agent 可在沙箱内生成并运行临时脚本
- [ ] 性能基准：WASM 执行开销相比 Docker 不超过 20%
